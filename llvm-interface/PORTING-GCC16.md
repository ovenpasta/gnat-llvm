# GNAT-LLVM GCC 16 Porting Notes

This document records the changes needed to build GNAT-LLVM against GCC 16
(master branch) as of March 2026. It covers both the compiler itself and the
WASM runtimes.

## Scope

Changes fall into three areas:

1. GCC 16 frontend API changes visible to GNAT-LLVM source
2. WASM runtime source changes needed for the updated libgnat
3. Repinfo accessor patch (same as GCC 15, updated line offsets)

---

## 1. Compiler changes (gnat-llvm repo)

### 1.1 Is_Link_Once stub removed

`gnatllvm-utils.ads` previously had a stub:

    function Is_Link_Once (Id : Entity_Id) return Boolean is (False);

This was added because GCC 15's `einfo-entities.ads` did not export
`Is_Link_Once`. GCC 16 now generates it (returning `Flag`, a subtype of
Boolean). With both in scope via `use` clauses, the compiler reported:

    gnatllvm-subprograms.adb:2827:33: error: ambiguous expression
      (cannot resolve "Flag")

Root cause: `gnatllvm.ads` has both `use Einfo.Entities` and
`use Sinfo.Nodes`. Both packages define `subtype Flag is Boolean`
(generated by `gen_il-gen.adb`). The stub in `gnatllvm-utils.ads`
returning `Boolean` and the real function in `Einfo.Entities` returning
`Flag` created an overloaded pair that Ada could not resolve in boolean
context.

Fix: remove the stub. The real `Is_Link_Once` from `Einfo.Entities` is
used directly. Affected files: `gnatllvm-subprograms.adb`,
`gnatllvm-variables.adb`.

### 1.2 Unique_Component_Name stub removed

`gnatllvm-utils.ads` previously had a stub:

    function Unique_Component_Name (E : Entity_Id) return Name_Id is
      (Chars (E));

GCC 16 added the real function in `sem_aux.ads`:

    function Unique_Component_Name
      (Component : Record_Field_Kind_Id) return Name_Id;

`Record_Field_Kind_Id` is a subtype of `Entity_Id`, so call sites with a
record-field entity matched both. This caused:

    gnatllvm-records-create.adb:2033:47: error: ambiguous expression
      (cannot resolve "Unique_Component_Name")

Fix: remove the stub. `gnatllvm-records-create.adb` already has
`with Sem_Aux; use Sem_Aux`, so the real function is visible.

## 2. Repinfo accessor patch

The same five accessors added for GCC 15 are still absent from GCC 16
master and must be patched in:

- `Is_Node`, `Get_Node_Code`, `Get_Node_Op1`, `Get_Node_Op2`, `Get_Node_Op3`

Required by `gnatllvm-records-debug.adb`. The patch applies cleanly to
GCC master (the insertion point shifted from line 2426 to line 2632 as
master grew). The updated patch is at:

    patches/gcc-16-repinfo-accessors.patch

---

## 3. WASM runtime changes (adawebpack repo)

### 3.1 Files removed from GCC 16 libgnat

The following files were in GCC 15's `libgnat/` but are absent in GCC 16.
They must now be copied from `rts-sources/` instead of falling through the
`COMMON_WASM_SRCS` loop in `Makefile.target`:

| File(s)                          | New source                         |
|----------------------------------|------------------------------------|
| `s-spark.ads`                    | `rts-sources/common/`              |
| `s-spcuop.adb`, `s-spcuop.ads`  | `rts-sources/common/`              |
| `s-vaispe.adb`, `s-vaispe.ads`  | `rts-sources/value/spec/`          |
| `s-valspe.adb`, `s-valspe.ads`  | `rts-sources/value/spec/`          |
| `s-vauspe.adb`, `s-vauspe.ads`  | `rts-sources/value/spec/`          |
| `s-vs_int.ads`                   | `rts-sources/value/spec/`          |
| `s-vs_uns.ads`                   | `rts-sources/value/spec/`          |
| `s-vs_llu.ads`                   | `rts-sources/value/spec_ll/`       |

Fix: remove the 11 entries from `COMMON_WASM_SRCS` in `Makefile.target`
and add explicit `cp` lines from the correct `rts-sources` subdirectories
in the `build-wasm-rts` macro.

### 3.2 System.Case_Util refactored in GCC 16

GCC 16 split `System.Case_Util` (`s-casuti`) into two packages. The
non-secondary-stack operations moved to `System.Case_Util_NSS`
(`s-cautns`). `s-casuti.ads` now has `with System.Case_Util_NSS`, so
`s-cautns.adb` and `s-cautns.ads` must also be present in the RTS.

Both files exist in GCC 16 `libgnat/`. Fix: add `s-cautns.adb` and
`s-cautns.ads` to `COMMON_WASM_SRCS` in `Makefile.target`.

### 3.3 Lower-bound warnings in s-imagei and s-imageu (wasm variants)

`s-imagei__wasm.adb` and `s-imageu__wasm.adb` used `S (1)` to write the
leading space, which GCC 16's `-gnatpg` mode rejects as a lower-bound
assumption error:

    s-imagei.adb:72:13: warning: index for "S" may assume lower bound
      of 1 [-gnatww]

Fix: replace `S (1)` with `S (S'First)` and `P := 1` with
`P := S'First` in both files. Semantically equivalent since these image
functions always receive 1-based strings.

### 3.4 _Adjust_Clone missing from s-stposu wasm body

GCC 16 added to `s-stposu.ads`:

    procedure _Adjust_Clone (Subpool : in out Root_Subpool);

The adawebpack-specific `s-stposu__wasm.adb` did not implement it,
causing a missing-body error at compile time.

Fix: add the same body as libgnat uses:

    procedure _Adjust_Clone (Subpool : in out Root_Subpool) is
    begin
       Finalization_Primitives.Initialize (Subpool.Collection);
    end _Adjust_Clone;

The WASM body already imports `System.Finalization_Primitives`, so no
additional `with` is needed.
